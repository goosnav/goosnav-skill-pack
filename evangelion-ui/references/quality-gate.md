# Visual and behavioral acceptance

Render the requested implementation at a desktop width (about 1440 px), narrow mobile (about 390 px), and with a long realistic title or error message. Inspect actual screenshots at 100% scale, not only source code. For desktop-only native tools, inspect minimum supported window size and high-DPI scaling instead. Read the primary task without zooming; test 200% browser zoom and keyboard use.

Compare the output side-by-side with the composite atlas and the chosen close-up. Is the result recognizably an Evangelion instrument face before reading any lore? Check the following:

| Dimension | Pass condition |
| --- | --- |
| Silhouette | Strong instrument hierarchy; deliberate black space; no generic rounded-card dashboard |
| Type | Condensed headings, restrained labels, readable body; no clipping, font fallback surprises, or uniformly monospaced text |
| Color | A clear primary/secondary hierarchy; meaningful states; custom theme propagated consistently |
| Framing | Consistent rule weights and spacing; no arbitrary hexagons, skewed controls, or ornamental visualizations |
| Analog | Visible subtle screen texture and luminous strokes; crisp text; effects-off genuinely removes treatment |
| Meaning | Every value/chart/status has a traceable source; absent data not portrayed as healthy; no filler lore |
| Behavior | Primary task works; relevant pending/empty/failure states work; no dead controls |
| Access | Focus visible, controls named, target size usable, color-independent states, reduced-motion/high-contrast honored |
| Layout | No unintended page overflow at narrow width or zoom; long labels/errors visible; plots retain interpretable axes |
| Performance | No perpetual per-frame texture JS; no animation-induced input lag or expensive full-screen filters |

Fix failures in meaning, functionality, accessibility, clipping, or missing font delivery before cosmetic polish. If style is weak, improve typography, dominant scale, framing, and black space before increasing glow or noise. Remove ornamental panels instead of filling them with invented data.

Check off, subtle, cinematic, one non-default palette, and a custom palette. Verify actual normal/selected/error contrast. Exercise at least one real primary interaction and its result; check console/build errors using the available tooling. Inspect changing states when animation is present. Limit extra testing to unresolved defects and project-required gates.

Deliver the working implementation, location of customization settings, actual verification performed, and material gaps. Never claim screenshots, performance profiling, a native build, or Claude Code execution happened when only static inspection occurred. A checked specimen proves starter behavior, not every future generated app.
